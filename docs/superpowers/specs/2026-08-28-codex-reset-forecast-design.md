# CodeX 重置预告 — 设计文档

**状态**：✅ 两期均已实现（一期展示层 2026-08-28；二期抓取器 2026-08-31）
**日期**：2026-08-28
**背景**：近期 CodeX 官方频繁做全量额度重置，负责人 tibo 会在 Twitter/X 上提前预告。
需要在面板上加一个入口：展示「下一次可能的重置时间点 + 概率」，点击跳转来源推文。

分两期：

1. **第一期（本期）**：展示层。面板读本地缓存文件渲染预告行，定好数据契约。
2. **第二期**：抓取器。从预告来源（tibo 的 X 帖等）拿到预测，写入缓存文件。

---

## 1. 展示设计（方案 A，已确认）

CodeX 卡片在 5h / 7d 行之后追加一行**重置预测行**（行标签「重置预测」，2026-08-31 定稿，初版叫「预告」）——不是百分比行，是「标签 + 文字 + 概率标签」：

```
CodeX  Pro                        ●
  ◯ 5h   99%              今天 16:52
  ◯ 7d   31%             下周二 10:00
  重置预测  明天 11:00  [高概率]      ↗
```

- **无预告数据时整行隐藏**（文件不存在 / 过期 / 时间已过去）。与盾牌「没测到 ≠ 测到问题」
  同一哲学：没抓到预告就不该有这行，不显示空值占位。
- 概率三档标签，复用 IP 卡的 tag 绘制与色阶：高=绿（ok）/ 中=黄（warn）/ 低=灰（无 tone）。
- **整行是点击热区**，跳转 `source_url`（来源推文）；行尾画 `↗` 提示可点。无 URL 则不可点、不画 `↗`。
- 第一期只做 macOS 面板；Windows flyout 跟 Fable 行同一节奏下一轮跟进。

## 2. 数据契约（两期之间的接口）

缓存文件 `~/.ai-limit-codex-forecast.json`，第二期抓取器写，面板只读：

```json
{
  "eta": "2026-08-28T11:00:00+08:00",
  "confidence": "high",
  "source_url": "https://x.com/.../status/...",
  "note": "tibo 预告",
  "fetched_at": "2026-08-27T22:00:00+08:00"
}
```

读取方 `usage.load_codex_forecast()` 的校验规则（任一不满足 → 返回 None → 行隐藏）：

1. 文件存在且是合法 JSON dict
2. `eta` 可解析为时间，且**尚未过去**（预告过期即作废，不显示历史预告）
3. `fetched_at` 可解析，且距今 **≤ 48 小时**（陈旧预测比没有更糟）
4. `confidence` 归一到 `high|mid|low`，缺失或非法一律降为 `low`（宁可低估不高估）

## 4. 第二期：抓取器（2026-08-31 实现）

**数据源**：`codex-reset.com`——社区「Tibo 雷达」，每 2 分钟从 @thsottiaux 的 X 同步，
28+ 次已验证重置打底，公开 `/api/forecast`（匿名可访，实测确认）。与 IP 安全功能同一
方法论：用站点自己的公开接口，拿与页面同源的数据，不碰 X 登录态。

**接口给的是窗口概率而非精确时刻**（rounded_24h / rounded_48h），因此契约扩了
**window 档**，与 eta 档并存：

```json
{"kind": "window", "p24": 25, "p48": 45,
 "source_url": "<官宣推文，缺失退 codex-reset.com/tibo>",
 "note": "codex-reset.com 实验模型", "fetched_at": "..."}
```

- 展示：`重置预测 24h 25% · 48h 45% [中概率] ↗`——没有精确时刻就不编造一个
- 概率→档位：max(p24,p48) ≥60 高 / ≥30 中 / 其余低
- window 档保鲜期 **12h**（比 eta 档的 48h 严：抓取器活着就该 30 分钟一轮）
- 抓取节奏：**30 分钟 + 0~20s 抖动**（概率以小时计变化，更快是骚扰数据源）；
  失败静默留旧缓存，由读取侧保鲜期自然淘汰
- `teased_window` 实测只见过 null，结构未知，**在观察到非空样本前不解析**
  （按假设写解析 = 复刻 ipsec dns_servers 的崩溃）
