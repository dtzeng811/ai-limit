# CodeX 重置预告 — 设计文档

**状态**：第一期（展示层）实现中
**日期**：2026-08-28
**背景**：近期 CodeX 官方频繁做全量额度重置，负责人 tibo 会在 Twitter/X 上提前预告。
需要在面板上加一个入口：展示「下一次可能的重置时间点 + 概率」，点击跳转来源推文。

分两期：

1. **第一期（本期）**：展示层。面板读本地缓存文件渲染预告行，定好数据契约。
2. **第二期**：抓取器。从预告来源（tibo 的 X 帖等）拿到预测，写入缓存文件。

---

## 1. 展示设计（方案 A，已确认）

CodeX 卡片在 5h / 7d 行之后追加一行**预告行**——不是百分比行，是「标签 + 文字 + 概率标签」：

```
CodeX  Pro                        ●
  ◯ 5h   99%              今天 16:52
  ◯ 7d   31%             下周二 10:00
  预告   明天 11:00  [高概率]        ↗
```

- **无预告数据时整行隐藏**（文件不存在 / 过期 / 时间已过去）。与盾牌「没测到 ≠ 测到问题」
  同一哲学：没抓到预告就不该有这行，不显示空值占位。
- 概率三档标签，复用 IP 卡的 tag 绘制与色阶：高=绿（ok）/ 中=黄（warn）/ 低=灰（无 tone）。
- **整行是点击热区**，跳转 `source_url`（来源推文）；行尾画 `↗` 提示可点。无 URL 则不可点、不画 `↗`。
- 第一期只做 macOS 面板；Windows flyout 跟 Fable 行同一节奏下一轮跟进。

## 2. 数据契约（两期之间的接口）

缓存文件 `~/.ai-limit-codex-forecast.json`，第二期抓取器写，面板只读：

```json
{
  "eta": "2026-08-28T11:00:00+08:00",
  "confidence": "high",
  "source_url": "https://x.com/.../status/...",
  "note": "tibo 预告",
  "fetched_at": "2026-08-27T22:00:00+08:00"
}
```

读取方 `usage.load_codex_forecast()` 的校验规则（任一不满足 → 返回 None → 行隐藏）：

1. 文件存在且是合法 JSON dict
2. `eta` 可解析为时间，且**尚未过去**（预告过期即作废，不显示历史预告）
3. `fetched_at` 可解析，且距今 **≤ 48 小时**（陈旧预测比没有更糟）
4. `confidence` 归一到 `high|mid|low`，缺失或非法一律降为 `low`（宁可低估不高估）
